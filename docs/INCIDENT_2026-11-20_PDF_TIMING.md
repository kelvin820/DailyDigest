## PDF 的另一個錯誤

14:21:16 與 14:22:45 的正式 log 都是 elementary 的 `page.setContent: Target page, context or browser has been closed`，發生於排版。這次已載入 PDF 引擎，不是前次缺少 browsers.json，也不是固定兩頁檢查。引擎維護者記錄了新 browser context 的同類問題並建議 default context：[Sparticuz #286](https://github.com/Sparticuz/chromium/issues/286)、[#298](https://github.com/Sparticuz/chromium/issues/298)。

修復使用每份 PDF 獨立的 persistent/default context、關閉不需要的 WebGL，且明確 browser-closed/crashed 才重啟一次。每份檔案各自 checkpoint；如果省墨版失敗，不再丟掉已成功的彩色檔。版面四區等高填滿 A4，留白保留在各 story 框內；正文過長仍可自然續頁，沒有固定頁數限制。
